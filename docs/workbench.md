# 个人工作台使用与数据说明

[返回 README](../README.md) · [升级规划](personal-workbench-upgrade-plan.md)

个人工作台把任务、项目、工作记录、计划、报告和复盘放在同一份本地数据中。报告草稿按已有事实和模板生成，不需要配置额外模型，也不会向外部平台发送。

## 从一天的工作开始

1. 在「任务」快速记录事项，按重要与紧急分到四象限；需要时填写项目、截止日期、计划日期、估时和等待事项。
2. 在「项目」建立目标，用项目标签关联任务。旧的通用标签可以批量归入项目，原标签保留。
3. 在「规划」选择日 / 周目标、任务和时间预算，确认计划。首次确认的任务会作为复盘基线，后续调整保留历史。
4. 执行中记一句进展、产出、阻塞或决策。未完成的大任务也能进入报告，任务是否勾选完成不是唯一证据。
5. 在「回顾」生成报告或复盘，查看事实与问题，修改后保存、定稿或导出 Markdown。复盘中的改进行动可以直接转成任务。

四象限用于选择处理策略，P0–P3 保留为执行顺序。Q2 建议安排具体日期；等待中的任务可设跟进日。容量提示会列出未估时事项，避免把它们当作零投入。

## 报告与复盘

日报、周报、月报共用时间范围和项目筛选：不选项目即所有项目，选择一个或多个项目即可生成独立报告。未归属活动也计入全局报告，归档不会删除已经发生的活动。

报告按事件发生时的项目和标签归属统计；本期完成后又重开的任务会单列，旧数据中完成时间未知的记录不冒充本期成果。专注和手工投入分开显示，避免直接相加造成重复。

每份文档保存事实快照和修订。再次生成会新增候选修订，保留当前人工内容；可以查看和恢复历史修订。文档编辑带版本检查，避免另一个窗口的修改被静默覆盖。文档定稿只表示本地定稿，不表示已发送。

复盘草稿包含事实与待回答问题。它不会替你认定原因或自动宣布复盘完成；私人反思不自动进入工作报告。

## 周期规则

报告和复盘分别设置：范围、日 / 周 / 月模板、触发时间、时区、每天 / 指定星期 / 每月 / 每 N 天或周，以及覆盖上一周期、当前周期或滚动区间。规则显示下三次触发时间，可暂停、立即执行、跳过或稍后提醒。

默认行为是 **到点生成本地草稿，自己查看和修改**。也可选择仅提醒。每条规则独立保存，项目周报、项目组周报和全项目周报可以并存。

- 插件在 **Host 运行期间每 30 秒检查一次**，关闭面板不会停止检查；电脑休眠或 Host 退出期间不会执行。
- 恢复运行后只自动补最近一期，避免突然出现大量积压草稿。更早周期可以在报告生成器指定日期补生成。
- 同一规则、同一覆盖周期只保存一次；手动重复运行不会重复创建。重新生成已有文档通过新修订完成。
- 规则修改影响未来运行；已经生成的文档、范围和运行记录不被改写。
- 失败会显示原因，自动重试最多五次并退避；修改规则、手动成功运行或重启 Host 可重新尝试。
- 每月 31 日遇短月取月末；夏令时不存在的时刻跳过，重复时刻取第一次。日期按规则的时区解释。
- 当前周期未结束时，草稿会注明截止时刻，不当作完整周期报告。

该版本直接由 Host 执行本地确定性生成，没有接入 Harness `schedule` 的 Agent 指令投递链路，也没有默认扫描会话或调用模型。这样生成草稿不依赖额外的会话、模型或凭据。

## 数据迁移、恢复与保存

原配置仍接受 `dataFile` 或 `DSH_TODOS_FILE`。如果配置为 `todos.json`，新版实际使用同目录的 `todos.v3.json`；直接配置 `.v3.json` 后缀则使用该文件。默认新版路径为 `$DSH_HOME/dsh-todos/todos.v3.json`。

首次读取旧文件时预览迁移；第一次成功修改将迁移结果和本次操作一起原子保存到 v3 文件。原文件不修改，迁移元数据保存源文件 SHA-256、记录数和版本。旧任务 ID、标题、标签、优先级、象限与会话引用保留；未知完成时间保持未知。

同一份数据应由升级后的插件写入，避免同时运行旧插件继续改旧文件。需要回退时先停止写入并保留完整 v3 文件；旧版本只能读到升级前快照，升级后新增记录仍保存在 v3 文件中。

保存包含任务状态和对应历史事件，写入失败不会发布新的内存状态或 revision。损坏、无法读取、未来版本或已提交文件被移走时拒绝覆盖，并显示错误；修复 / 恢复文件后重试。目录 fsync 在不支持的平台尽力执行。

「清除已完成」改为归档，「删除」进入可恢复区，历史仍可追溯。普通操作不会永久清除工作历史。当前任务保护上限为 100,000 条，达到上限明确报错，不静默截断；该值不是性能保证。

当前番茄钟状态仍在浏览器保存，完成 / 提前结束后的有效专注记录由 Host 保存。浏览器计时不是后台工时采集；休息不算投入，异常或未保存的记录应核对，不代表全部实际工时。

## Agent 与接口

`todo_track` 保留原操作，增加项目、任务状态、日期、估时与恢复；`clearDone` 的新语义为归档。新增 `work_project`、`work_log`、`work_plan`、`work_report`、`work_review`、`work_routine`，均经过同一存储事务入口。

本机接口继续使用 `GET /plugins/dsh-todos/state` 和 `POST /plugins/dsh-todos/mutate`。写操作可携带 `baseRevision`，文档编辑另支持 `baseRevisionId`。操作特有结果位于 `data`；历史使用 `query` 分页或 `document.get` 读取完整修订。

## 本地预览与检查

```bash
npm ci
npm test
npm run preview
# 可选的浏览器流程验证：首次先运行 npx playwright install chromium
npm run test:browser
```

预览默认在 `http://127.0.0.1:4178`，使用临时演示数据和真实 API，不读取你的 DSH 数据。退出预览后清理临时数据。通过 `?theme=dark` 查看深色，`?lang=en` 查看英文界面。React 仅为开发预览依赖，Playwright 仅用于浏览器测试，插件仍使用宿主 React；构建产物无需 CDN。浏览器测试输出临时截图与 `result.json`，不修改真实用户数据。

自动测试与隔离预览不能证明当前运行的 DSH profile 已升级。安装新版并重启 Host 后，再核对真实数据路径、规则和首次自动生成结果。
